# 2026-09-18 全画面の本文を端末の幅いっぱいにする

同日の「本文の最大幅」の続き。160桁にしてもまだ狭い、という指摘から、既定を上限なしに変えた。

## 何が起きていたか

「入れ直したのに直らない」という報告。**実際には両方のPCで、変更前のバイナリが動いていた。**

画面から幅を割り出して確かめた。`PROGRESS.md`の引用の折り返しが「決めた要求・」で切れて次の行が「方針・」から始まるのは、折り返し幅100桁のとき。160桁なら「詳細ログは」まで1行に入る。手元でも幅200桁の端末に並べて、`~/.cargo/bin/folio`（9/15のバイナリ）は100桁、`target/debug/folio`は160桁で折り返すことを確認した。

原因は2つ。

- **`cargo install --path .`は、同じ版が既に入っていると何もせずに終わる**（`--force`が要る）。版はずっと`0.1.0`だったので、入れ直したつもりで入っていなかった。
- 配った先は、履歴を書き換えた後だったので`git pull --ff-only`が通らず、コード自体が古いままだった。

## 決めたこと（ユーザー決定）

全画面の本文は**既定で端末の幅いっぱい**にする。ファイラーのプレビュー欄には最大幅の制限が無いので、全画面にだけ効くと「ツリーを消すと狭くなる」ことになって驚く。**2つの見え方を揃える**のが決め手だった。狭く読みたい人は設定で幅を書く。

100桁 → 160桁 → 上限なし、と同日に2回直した。最初に「端末幅いっぱい」を選択肢に出した時は160桁が選ばれたが、実物を見て変わった。**幅の好みは口頭では決まらない**。

## やったこと

- `view.max_width`の`0`を「上限なし」の意味にし、既定を`0`にした。`viewer.rs`に`body_column`を切り出して、0なら領域をそのまま返す。テスト1件。
- **`Cargo.toml`の版を`0.1.0`→`0.2.0`**。同じ版だと`cargo install --path .`が黙って何もしないので、配る側から見て「入れ直したのに変わらない」が起きる。版を上げれば`--force`無しでも入るし、`folio --version`が効く確認になる。
- READMEの使い方に`cargo install --path . --force`（入れ直す時）を明記。設定の節の既定値も直した。

## 確認したこと

幅200桁の端末で、水平線が200桁いっぱいに伸び、引用が1行に収まることを確認。`cargo fmt` / `cargo clippy --all-targets -- -D warnings` / `cargo test`（96件）が通る。

## 配った先での入れ直し

履歴を書き換えたのでcloneし直しが要る。`git pull`では繋がらない。
