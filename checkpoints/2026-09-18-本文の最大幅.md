# 2026-09-18 本文の最大幅の既定を160桁に

## きっかけ

全画面（Windows Terminal、200桁超）で`folio view`を開くと、本文が真ん中にギュッと絞られて左右が大きく余る、という指摘。幅広の表が特に読みにくい。

## 分かったこと

原因は既定の折り返し最大幅100桁（`config.rs`の`View::default`）。`viewer.rs`の`centered_column`が、本文領域がそれより広ければ100桁ぶんの列を中央に切り出し、余りを左右に捨てる。長文を読みやすくするための機能だが、全画面には効きすぎていた。

似た表（超長文の状態列を持つ8列）を作って`folio render --width`で測ったところ、幅を上げる効果は大きい:

| 幅 | 「問い」列の幅 |
|---|---|
| 98桁 | 6桁 |
| 160桁 | 14桁 |
| 240桁 | 22桁 |

## やったこと

- `View::default`の`max_width`を100→160。`max_width`は上限であって固定幅ではないので、狭い端末（80桁・120桁）の見え方は変わらない。
- 最初は`~/.config/folio/config.toml`を作って個人設定で上げたが、「他のPCに配りたいのでインストール時の既定にしたい」との指示で既定値の変更に切り替え、個人設定ファイルは削除した（既定と同じ内容になったため）。
- README「設定」節の既定値の表記、REQUIREMENTS.mdのP2の記述をあわせて更新。
- 設定ファイルを置かない端末でこの幅になることを`empty_text_is_default`で固定。

## 確認したこと

`cargo fmt` / `cargo clippy -- -D warnings` / `cargo test`（91件）が通る。

## 積んだだけのもの（REQUIREMENTS.mdのバックログへ）

- 表の列幅の配り方。いまは列の自然幅の比で配るので、状態列のような超長文の列が場所を独占し、他の列が最小幅4桁まで潰れる。上限を設けて他の列へ回したい。
- 本文の最大幅を表示中にキーで切り替える（文章は狭く、広い表は全幅で見たい）。
